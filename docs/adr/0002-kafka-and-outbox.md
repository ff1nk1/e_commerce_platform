# ADR 0002. Kafka между сервисами, outbox для заказов и остатков

## Контекст

Каталог, заказы, поиск, рекомендации, письма и аналитика должны узнавать об изменениях друг друга. Синхронная цепочка HTTP на каждый чих связывает сервисы по времени ответа.

## Решение

События идут в Kafka (`kafka:29092`). Тип — header `event-type`.

Товары и категории catalog публикует сразу. Заказы и ответы saga по остаткам пишутся в `outbox_events` в той же транзакции, что и домен, и уходят воркером `kafka:outbox:work`.

Единственный прямой HTTP между сервисами — recommendation проверяет свежесть карточки в catalog.

## Почему так

Поиск и ассистент держат свою копию каталога и не ждут catalog на каждый запрос. Outbox не теряет `order.created` и `stock.*`, если брокер мигнул в момент коммита заказа.

## Что отклонили

Синхронные вызовы catalog на каждый заказ и одну общую базу, из которой все читают товары.
