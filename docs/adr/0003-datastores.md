# ADR 0003. Своё хранилище под задачу

## Контекст

Один Postgres на все сервисы смешивает схемы и мешает выкатывать сервис отдельно.

## Решение

| Данные | Где |
|--------|-----|
| Пользователи, каталог, заказы, диалоги ассистента | свой Postgres у сервиса |
| Сессии auth и catalog, идемпотентность заказов | свой Redis |
| Журнал писем | MongoDB `email_logs` |
| Поисковый индекс | OpenSearch |
| Агрегаты аналитики | ClickHouse |
| Эмбеддинги товаров | Postgres + pgvector |
| Картинки | MinIO |

## Почему так

Поиск и аналитика плохо ложатся на OLTP Postgres. Журнал писем пишется как документ и не участвует в реляционных связках заказа. pgvector остаётся рядом с диалогами ассистента, без отдельной vector-базы.

## Что отклонили

Общий Postgres и Mongo как основную базу каталога или заказов.
